# 「밀정」 MVP 설계 문서

- 작성일: 2026-10-14
- 상태: 검토 대기
- 범위: 하위 프로젝트 1 — 방 코드로 모여 한 판을 끝까지 플레이할 수 있는 최소 버전

## 1. 배경과 목표

어몽어스 방식의 소셜 추리 게임을 1910년대 독립운동 배경으로 재해석한 **상용 모바일 게임**을 만든다.
다수의 독립투사(비밀결사) 사이에 소수의 밀정이 숨어 있다.

전체 제품은 다음 하위 프로젝트로 나누어 순서대로 진행한다. 이 문서는 1번만 다룬다.

1. **게임 코어 + 실시간 멀티플레이 (이 문서)**
2. 계정 / 로비 / 친구 초대 / 랜덤 매칭
3. 운영 도구 (신고·제재, 채팅 필터, 지표, 서버 모니터링)
4. 아트·사운드 정식 리소스
5. 수익화 (스킨 상점, 인앱 결제, 광고) 및 스토어 출시

### MVP 성공 기준

- 4~10명이 6자리 방 코드로 한 방에 모인다.
- 역할 배정 → 이동 → 임무/밀고/방해 → 신고/회의/투표 → 승패 판정까지 한 판이 끝까지 진행된다.
- 모바일 브라우저(터치)와 PC 브라우저(키보드)에서 모두 플레이할 수 있다.
- 서버가 모든 판정을 하며, 클라이언트가 자신에게 허락되지 않은 정보(타인의 역할)를 받지 않는다.
- 규칙 단위 테스트, 서버 통합 테스트(한 판 자동 진행), 브라우저 E2E 테스트가 통과한다.

### MVP 제외 항목

계정·로그인, 랜덤 매칭, 스킨·상점, 결제·광고, 음성 채팅, 추가 맵, 특수 역할, 정식 아트, 앱스토어 제출.
(Capacitor 프로젝트 설정은 포함하되, 스토어 서명·제출은 하위 프로젝트 5에서 진행한다.)

## 2. 게임 규칙

모든 수치는 `shared` 패키지의 설정값(`GameConfig`)으로 두어 플레이테스트로 조정한다. 아래는 기본값이다.

### 2.1 배경과 맵

1919년 전후 경성의 비밀 아지트. 맵 1개, 구역 8개:
서점 뒷방(회의 장소, 비상종 위치), 인쇄소, 다방, 한약방, 전차 정류장, 골목, 지하 창고, 전신국.
구역은 통로로 연결되며, 통로 일부는 방해 공작 "일경 검문"으로 일시 차단될 수 있다.

맵은 타일 기반 데이터(JSON)로 정의하여 서버(충돌·거리 판정)와 클라이언트(렌더링)가 같은 데이터를 쓴다.

### 2.2 인원과 역할

| 인원 | 밀정 수 |
|------|---------|
| 4~6명 | 1 |
| 7~10명 | 2 |

- 나머지는 독립투사.
- 밀정끼리는 서로를 안다. 투사는 누가 밀정인지 모른다.
- 역할은 게임 시작 시 서버가 무작위로 배정한다.

### 2.3 독립투사

- **거사 준비 임무**: 1인당 미니게임 5개를 무작위 배정한다. 임무 종류(MVP 5종):
  1. 독립선언서 등사 (반복 탭)
  2. 암호문 해독 (기호 짝 맞추기)
  3. 군자금 세기 (목표 금액만큼 엽전 드래그)
  4. 태극기 접어 숨기기 (순서대로 스와이프)
  5. 전보 송신 (제시된 장단 패턴 입력)
- 임무 지점에 가까이 가면 "임무" 버튼이 활성화되고, 미니게임 완료 시 서버에 완료를 보고한다.
- 전체 거사 게이지 = 모든 투사(유령 포함)의 완료 임무 수 / 전체 배정 임무 수.
- **승리 조건**: 거사 게이지 100% 또는 모든 밀정 축출.

### 2.4 밀정

- **밀고** (킬): 사거리 1.5타일 안의 살아 있는 투사 대상, 쿨다운 30초(게임 시작 및 회의 종료 직후에도 쿨다운 적용).
  대상은 "끌려가" 유령이 되고, 그 자리에 **흔적**(떨어진 모자·전단)이 남는다. 폭력 묘사는 하지 않는다.
- **방해 공작** (공용 쿨다운 40초, 동시에 1개만 활성):
  - **정전**: 투사 시야 반경 축소. 투사가 전신국 차단기를 조작하면 해제. 자동 해제 없음.
  - **일경 검문**: 지정 통로 1곳 15초간 차단. 시간 경과로 자동 해제.
- **위장**: 임무 지점에서 임무를 하는 척할 수 있다. 게이지는 오르지 않는다.
- 밀정은 회의를 열 수 있고 투표할 수 있다.
- **승리 조건**: 살아 있는 투사 수 ≤ 살아 있는 밀정 수.

> 섹션 1 초안에 있던 "방해 공작 미해결 시 밀정 승리"는 MVP에서 제외한다. 정전은 시야만 줄이고 패배 조건이 아니며, 검문은 자동 해제된다. 시간 제한 방해 공작은 이후 확장 항목으로 둔다.

### 2.5 회의와 투표

- **회의 소집**:
  - 흔적 근처(1.5타일)에서 "신고" → 회의.
  - 서점 뒷방의 **비상종**: 1인 1회, 게임 시작 후 15초 이후부터 사용 가능.
  - 활성 중인 방해 공작이 있으면 비상종은 사용할 수 없다(신고는 가능).
- 회의가 열리면 모든 생존자는 서점 뒷방으로 순간 이동하고, 모든 흔적은 제거되며, 활성 방해 공작은 해제된다.
- **진행**: 토론 60초 → 투표 30초. 토론 중에도 투표 가능.
- **투표**: 생존자 1인 1표, 대상은 생존자 또는 "건너뛰기". 미투표는 건너뛰기로 집계.
- **결과**: 최다 득표자가 단독 1위이고 건너뛰기보다 많으면 **조직에서 축출**(유령이 됨). 동점 또는 건너뛰기 최다면 아무도 축출하지 않는다.
- **역할 공개**: 방 옵션 `revealRoleOnEject` (기본 true).
- 축출 직후 승리 판정을 한다.
- **채팅**: 텍스트 채팅은 회의 중에만, 생존자만 사용 가능. 유령은 유령끼리만 채팅(상시).

### 2.6 유령

- 끌려가거나 축출된 플레이어는 유령이 된다.
- 유령은 벽을 통과해 이동할 수 있고, 다른 생존자에게 보이지 않는다.
- 투사 유령은 남은 임무를 계속 수행할 수 있다. 밀정 유령은 아무 행동도 할 수 없다(MVP).

### 2.7 시야

- 생존 투사: 반경 5타일 (정전 시 1.5타일).
- 생존 밀정: 반경 6타일 (정전 영향 없음).
- 유령: 전체 맵.
- 서버는 시야 밖 플레이어 위치를 클라이언트에 보내지 않는다(2.8 참고).

### 2.8 승리 판정 우선순위

상태가 바뀌는 모든 시점(밀고, 축출, 임무 완료, 연결 종료)에 아래 순서로 판정한다.

1. 살아 있는 밀정 0명 → 투사 승리
2. 살아 있는 투사 ≤ 살아 있는 밀정 → 밀정 승리
3. 거사 게이지 100% → 투사 승리

### 2.9 연결 끊김

- 게임 중 연결이 끊기면 30초 동안 캐릭터가 그 자리에 남고, 재접속하면 이어서 플레이한다.
- 30초가 지나면 해당 플레이어는 이탈 처리된다(유령과 동일, 단 배정 임무는 게이지 분모에서 제외). 이후 승리 판정을 한다.
- 대기실에서 방장이 나가면 남은 인원 중 가장 먼저 들어온 사람이 방장이 된다.

## 3. 아키텍처

### 3.1 기술 스택

- 언어: TypeScript (전 패키지)
- 클라이언트: Phaser 3, Vite
- 서버: Node.js, Colyseus
- 모바일 패키징: Capacitor (iOS / Android)
- 테스트: Vitest(단위·통합), Playwright(E2E)
- 패키지 관리: npm workspaces 모노레포

### 3.2 저장소 구조

```
MILJEONG/
├─ packages/
│  ├─ shared/   게임 규칙 (순수 TS, 엔진·네트워크 무관)
│  ├─ server/   Colyseus 게임 서버
│  └─ client/   Phaser 클라이언트 + Capacitor
└─ docs/
```

### 3.3 `shared` — 게임 규칙의 단일 출처

- `GameConfig`: 모든 수치 기본값.
- 맵 데이터(JSON)와 충돌·거리·시야 계산.
- 순수 함수 형태의 규칙: 역할 배정(난수 주입 가능), 행동 검증(이동/밀고/신고/비상종/방해/임무), 투표 집계, 승리 판정.
- 상태를 입력받아 새 상태 또는 거부 사유를 돌려준다. 부수효과가 없어 단위 테스트로 전수 검증한다.
- 클라이언트·서버가 공유하는 메시지 타입 정의.

### 3.4 `server` — 서버 권위 방식

- 클라이언트는 **의도**만 보낸다: `move(dir)`, `inform(target)`, `report()`, `ringBell()`, `sabotage(kind)`, `taskComplete(taskId)`, `vote(target|skip)`, `chat(text)`.
- 서버가 `shared` 규칙으로 검증 후 상태를 갱신한다. 거부된 의도는 사유 코드와 함께 해당 클라이언트에만 응답한다.
- 서버 틱: 20Hz. 이동은 서버가 위치를 계산(속도·충돌 적용)한다.
- **정보 은닉**: 공개 상태(Colyseus 동기화 상태)에는 역할을 넣지 않는다. 역할·동료 밀정·배정 임무는 해당 클라이언트에 개별 메시지로 보낸다. 플레이어 위치는 각 클라이언트의 시야 안에 있는 것만 보낸다(개별 필터링).
- 미니게임 자체는 클라이언트에서 진행되며, 서버는 "임무 지점 근접 + 최소 소요 시간 경과"를 검증하고 완료를 인정한다.
- 방: 6자리 코드(혼동 문자 제외), 정원 10명, 대기실에서 방장이 시작(최소 4명).
- 채팅: 길이 제한 100자, 초당 전송 제한.

### 3.5 `client` — 화면과 입력

- 씬: 타이틀 → 방 만들기/참가 → 대기실 → 역할 공개 → 게임 → 회의/투표 → 결과.
- 입력: 모바일은 가상 조이스틱 + 상황별 액션 버튼(임무/밀고/신고/방해/비상종), PC는 WASD/방향키 + 단축키.
- 원격 플레이어 위치는 보간하여 표시한다.
- 아트는 임시 도형·플레이스홀더. 리소스 경로를 분리해 이후 교체 가능하게 한다.
- UI 문구는 한국어. 문자열은 별도 파일로 분리(이후 다국어 대비).

### 3.6 데이터 흐름 예시 — 밀고

1. 밀정이 밀고 버튼을 누르면 클라이언트가 `inform(target)`을 보낸다.
2. 서버가 역할, 생존 여부, 거리, 쿨다운, 회의 중 여부를 검증한다.
3. 통과 시 대상이 유령이 되고 흔적이 생성되며 쿨다운이 초기화된다.
4. 승리 판정 후 변경 사항을 전파한다(대상 본인에게는 "끌려감" 알림).

### 3.7 오류 처리

- 잘못된 의도: 상태 변경 없이 거부 사유 코드 반환, 클라이언트는 조용히 무시하거나 짧은 안내 표시.
- 없는 방 코드 / 가득 찬 방 / 이미 시작한 방: 참가 화면에서 한국어 오류 안내.
- 서버 예외: 해당 방만 종료하고 클라이언트에 "연결이 끊어졌습니다" 안내 후 타이틀로 이동.

## 4. 테스트 전략

- **`shared` 단위 테스트**: 역할 배정 수, 밀고 검증(거리·쿨다운·대상), 투표 집계(동점·건너뛰기), 승리 판정 우선순위, 방해 공작 규칙, 게이지 계산(이탈자 제외).
- **`server` 통합 테스트**: 가상 클라이언트 N명으로 방 생성 → 시작 → 밀고 → 신고 → 투표 → 승패까지 자동 진행. 정보 은닉 검증(투사 클라이언트가 받은 데이터에 타인 역할이 없음).
- **`client` E2E**: Playwright로 브라우저 4개를 띄워 방 생성·참가·시작·회의·투표까지 진행.

## 5. 이후 확장 (MVP 이후)

특수 역할(예: 의사, 밀정을 돕는 친일 협력자), 추가 맵, 시간 제한 방해 공작, 음성 채팅, 계정·매칭, 상점·결제, 정식 아트·사운드, 스토어 출시.
실존 인물·단체는 쓰지 않고 가상 인물·조직으로 구성한다. 폭력 묘사는 "끌려감" 수준으로 절제해 낮은 연령 등급을 목표로 한다.
